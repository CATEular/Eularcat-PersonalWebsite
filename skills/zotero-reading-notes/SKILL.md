# 单篇阅读整理

用户提供文章短名、标题、Zotero 链接或 key。默认由当前代理完成，沿用用户的模型选择。

## 首次使用与笔记偏好

先读取用户已提供的约定及本 skill 目录的 `config.local.json`。首次安装或缺少配置时，按 [偏好配置](references/preferences.md) 简短确认：笔记目标位置、批注颜色含义、语言与整理详略，以及是否需要知识卡。只问缺失项，已确认的偏好直接沿用；当前请求的明确要求优先于已存配置。

颜色没有通用语义。示例颜色表仅供选择，不能当作用户习惯。未确认的颜色只保留为来源信息，依据用户评论和原文整理；不推断它表示问题、方案或定义。用户可选择不按颜色分类。

按用户确认的值从 `config.example.json` 建立本地配置，不覆盖已有配置。配置中的相对路径以配置文件所在目录为基准；写入笔记前必须确认 vault 与目标目录。用户暂不设置颜色时仍可整理内容；缺少目标目录时先在对话中给出草稿。个人配置、证据 JSON、文库路径和文献标识不加入公开下载。

## 定位与读取

1. 只读搜索，唯一确认目标；标题、作者、年份共同核对。多候选只问一次必要的选择，不按最近阅读猜选。
2. 优先使用可用的 Zotero 工具；读取原文及所有批注，包括高亮、框选和手绘的 position/paths。API 返回空批注不能作为“没有批注”的证据。
3. 本机读取方法见 [本机只读证据](references/local-reading.md)。重复的提取可运行 `python scripts/read_paper.py`；它只读取 Zotero，将证据 JSON 写到指定输出目录。
4. 短高亮不足以支持解释时，查原文上下文；手绘结合页面图像和坐标理解，不猜用户意图。读不到的内容明确留待核实。

## 目标位置与范围

按已确认的 vault、目录和命名约定，先检查已有该篇笔记、知识卡和别名。按主题沿用相关已有目录，不把其他主题强塞进某个领域；目的地确有歧义时只问必要的选择。

只处理目标论文及必要的相关卡片或链接，不重整全库、不自动更改 Zotero 分类、不建立自动同步服务。

## 阅读笔记

- 用户评论是整理优先依据；颜色按已确认的映射理解。若颜色与具体评论冲突，以评论为准，必要时标注待核。
- 按学习主题提炼，视内容采用核心知识、问题与方法、定义、待核问题等部分；无内容的部分省略，遵循用户的语言与详略偏好。
- 被标为问题的批注不自动关闭；被标为方案也不等于问题已解决。仅有明确证据才把问题与方法配对，注明适用条件与未解部分。
- 区分原文摘录、用户评论、AI 解释；短片段不支持的结论不能写成论文结论。具体文章中的边界不能提升为全局规则。
- 正文默认可见，以有意义的主题标题组织。不要每条批注都折叠，不用类型、页码或 key 充当阅读标题，不在正文裸露内部 ID。
- 使用少量精确原位置链接：`zotero://open-pdf/library/items/<attachment-key>?page=<page>&annotation=<annotation-key>`。page 使用 PDF 页索引加 1，显示页码可另写 pageLabel。群组文库须核实对应的群组链接格式，不套用个人文库链接。
- 仅在图本身有信息时保留必要裁图，避免重复整页图。元数据放 frontmatter 或独立 JSON；原始归档不能代替阅读界面。
- 未指定详略时给出一篇简短可读笔记。知识卡按用户选择添加；启用时先按概念和别名去重，可补充已有相关卡片，或创建少量确有新增、可独立复用的卡片。
- 添加必要语义关联；已有 Canvas 只在关系确有新增且能保留人工布局时更新，不为每篇自动重建图谱。

## 增量写入与交付

写入前读现有文件。以 paperKey + annotationKey + 内容 hash 比较新增与变化；helper 的 hash 覆盖文本、评论、颜色、位置、类型及页码标签。

只更新明确由本流程维护的片段，保留人工内容和其他来源；没有可靠边界则小范围补充或说明冲突，不覆盖全文。重复运行无变化时不重复创建笔记、卡片或图。

记录来源 key/hash 于隐藏元数据或现有状态 JSON；原批注删除不自动删除用户笔记。已有链接和锚点尽量保留，原始证据档案沿用该 vault 的约定，不将别人的目录布局当作默认值。

完成后核对链接、内容可见性、来源与结论边界，简报更新了哪些文件、仍待核实什么。没有持续运行的任务时，不宣称已开启自动同步。
