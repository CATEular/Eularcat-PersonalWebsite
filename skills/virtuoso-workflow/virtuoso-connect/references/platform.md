# ChatGPT / Codex 平台约定

## 已验证的运行环境

这套工作流围绕 VMware 上运行 Virtuoso 的 Linux 虚拟机开发与验证，支持 Agent 通过 bridge／SSH 操作虚拟机。CentOS／Red Hat 原生主机上直接运行 Virtuoso 的方式尚未尝试，暂不列为已验证环境。

五个技能作为一个工作流套件安装在同一父目录。它们通过相对路径分享配置和接口参考，不需要原来的五个技能。技能是指导 Agent 的文件，不是可直接执行的 `/command`。

个人环境统一放在 `virtuoso-connect/config.local.json`，环境操作前按 [配置协议](environment.md) 读取；公共 `SKILL.md`、脚本和参考不含个人绝对路径、主机或库名。配置中历史版本/结果仅用于定位，当前数据库和用户任务仍需核验。

## 可用工具决定执行方式

- 在 Codex 有命令执行工具时，用它运行本机脚本，并使用工具提供的会话句柄跟踪长任务。不要假设存在 `IsDaemon`、`run_in_background` 或 Claude 专属 Agent 工具。
- 本机是 Windows PowerShell 时，推荐 `& '解释器绝对路径' '脚本路径'`；Bash、远端 Linux 命令不能原样当 PowerShell 运行。启动隐藏服务若用 `Start-Process`，设置 `-WindowStyle Hidden` 并单独验证生命周期。
- ChatGPT 会话没有本机命令或远程桥接工具时，可读取资料、编写脚本、提供操作步骤；明确说明尚未执行，不声称已经连接、仿真或设计完成。
- GUI 操作仅使用当前实际可用的电脑操作工具及其技能。屏幕截图属于辅助证据，不能替代连通性、网表或仿真结果。
- 用户任务决定授权范围。复用已有授权，完成可逆工作；删除、覆盖与无关会话变更不由技能自行扩大授权。
- 仿真任务长时间执行时，用可恢复的作业/会话机制观察进度，向用户提供有意义的阶段结果；不要无休止轮询，也不要未经授权创建定时任务。

## 接口与证据

1. 使用 `scripts/api_probe.py` 或实际源码核对函数存在性与参数。
2. 遇到版本差异时，用 bridge 的函数检索、安装的 Cadence 文档或实际最小示例继续核对。
3. 验证 transport 返回状态、SKILL 返回值与设计读回结果；`ok=True` 不保证被修改对象符合预期，`nil` 也可能代表空结果或失败，需按函数契约判断。
4. 首选高层 Python API，其次经核验的单次 SKILL，复杂操作用 `.il`。不要用函数名大小写相似、历史日志或错误经验猜测接口。
5. 原参考文档中的 `examples/01_virtuoso/...` 属于外部桥接仓库；本套件未打包那些示例，先定位实际仓库再引用，缺失时查源码。

## 维护新经验

记录操作、工具/PDK/bridge 版本、输入、完整错误、验证过的替代方案和适用条件。未验证的经验标记“待核验”。不要将某次失败上升成所有版本的永久限制。用户要求更新技能时再修改技能库；日常任务中的经验先写项目日志。
